# A.X K2 A100 서빙 패턴 스크리닝 결과 (2026-11-10)

- 작성일: 2026-11-10
- 대상: A100 80GB 노드 1~2대(Azure ND96amsr A100 v4, 영국 남부, InfiniBand)에서 실행할 수 있는 서빙 배치. 실행 방식 변형을 포함해 23종을 시도했다.
- 기준 커밋: `5dc653b`(스크리닝 3개 작업), `6fe428d`(DP 재실행), `2d104e4`·`b7760b0`·`50d51d9`(PD 재시도).
- 방법: 배치마다 서버를 한 번 띄워 같은 측정 묶음(`screen`)을 실행했다. 측정 방법과 후보 선정 규칙은 [벤치마크 프로토콜](../BENCHMARK_PROTOCOL.md)에 실행 전에 기록했다.
- 증거: [`evidence/a100-serving-screening-2026-11-10.json`](../../evidence/a100-serving-screening-2026-11-10.json)(선정 결과와 배치별 수치, 작업 이름은 역할 이름으로 바꿈)
- 표시
  - **확인**: GPU에서 측정했거나 로그로 확인했다.
  - **추정**: 소스 분석이나 계산에서 나온 값이다. GPU에서 측정하지 않았다.
  - **미확인**: 기록된 증거로 판단할 수 없다.
- 주의: 배치마다 1번만 실행했다. 이 보고서의 비교는 경향이며 통계적 결론이 아니다. 신뢰구간이 있는 비교는 본 라운드(반복 측정)에서 낸다.

## 1. 결론

1. **A100에서 가능한 서빙 패턴을 모두 실제로 띄워 보았다(확인).** 23종 중 19종이 측정을 마쳤다. 나머지 4종 중 3종(Ray 실행기의 C4·C8·C16)은 실행 방식을 바꿔 측정했고, 1종(DCP)은 A100 포트에서 쓸 수 없다.
2. **정확도: 측정을 마친 모든 배치가 같은 출력을 냈다(확인).** 각 작업의 기준 배치 대비 평균 절대 log-prob 차이는 0.034~0.042 nats, top-1 일치율은 0.984~0.988이다. 기준은 0.05 nats 이하, 0.95 이상이다.
3. **요청 1개의 지연은 TP 중심 배치가 가장 짧다(확인).** A(FP8 TP8×PP2)와 D(NVFP4 TP8)의 토큰 간 시간(c1 TPOT)은 입력 8K에서 21.4 ms, 21.0 ms다.
4. **처리량은 DP×EP 배치가 높지만 요청 1개의 지연이 길다(확인).** 동시 요청 32개·입력 8K의 출력 처리량을 같은 작업의 기준과 비교했다.
   - FP8 16 GPU: C2(DP2) 1.29배, C4(DP4) 1.55배, C8(DP8) 1.76배, C16(DP16) 1.79배. DP가 커질수록 늘다가 C8~C16에서 거의 멈춘다.
   - NVFP4 8 GPU: D24(DP2) 1.27배, D8(DP8) 1.38배.
   - 같은 배치의 c1 TPOT은 기준의 1.54~2.25배(32~49 ms)다. 요청이 1개일 때는 SLO의 TPOT 상한(표준 100 ms, 엄격 50 ms) 안이다. 부하가 있을 때 SLO를 지키는지는 본 라운드의 λ* 측정으로 판정한다.
   - C16과 D8은 131,072 토큰을 담지 못한다(각 61,376, 31,616).
5. **NVFP4는 노드를 늘리면 처리량이 거의 비례해 늘어난다(확인).**
   - 같은 작업에서 NVFP4 서버 2대(D×2, 16 GPU)의 SLO 처리량(λ*, 표준)은 1대의 2.04배다.
   - 다른 작업의 FP8 A(같은 16 GPU)와 비교하면 c32 8K 출력 처리량이 1.92배(411.1 대 214.2 tok/s)이고 c1 TPOT은 비슷하다(작업 간 비교).
   - 단, NVFP4와 FP8의 정확도 동등성은 아직 측정하지 않았다(미확인). 판정에는 별도 정확도 평가(KoBALT 200문항, CLIcK 300문항, 비열등 허용 폭 −3점)가 필요하다.
6. **프리필/디코드 분리(PD)는 동작하지만 노드 2대에서는 복제본 2개보다 낫지 않다(확인, 작업 간 비교).** PD(프리필 1대+디코드 1대)의 λ*는 표준 SLO에서 D×2의 0.95배, 엄격 SLO에서 0.63배다. 요청 1개의 첫 토큰 시간(TTFT)은 D 1대의 1.14~1.38배다. PD는 세 번째 재시도에서 측정을 마쳤다(4절).
7. **사전 등록 규칙에 따른 본 라운드 후보는 A, B0, D42이고 D×2도 실행한다(확인).** 다만 규칙의 지연 상한(c1 TPOT이 기준의 1.5배, NVFP4는 1.2배 이하)이 SLO 자체(TPOT 100 ms, 엄격 50 ms)보다 엄격하다. 그래서 처리량이 높은 C8·C4·C2·D24가 빠졌다. 이 배치를 본 라운드에 추가할지 결정해야 한다(6절).

- TP가 작은 DP 배치에서 예측이 측정보다 8~46% 높았다(C4 8%, D24 13%, C8 15%, C16 34%, D8 46%). 엔진마다 생기는 메모리 부담(그래프, 작업 공간)을 과소 추정한 것으로 보인다(추정).
- 단일 변경 비교(같은 작업, 1회씩):
  - `--max-model-len -1`(262,144) 대 131,072: c32 1K 출력 처리량 ×0.94, c1 TPOT ×1.01. 최대 길이를 늘리면 처리량이 약간 줄었다.
  - 전문가 round-robin 배치 대 기본(선형) 배치: FP8(C1rr 대 C1) c32 8K ×1.04, c1 TPOT ×0.96. NVFP4(Err 대 E) c32 8K ×1.02, c1 TPOT ×1.00.

## 6. 본 라운드 후보와 필요한 결정

사전 등록 규칙(`bench_stats.py select`)의 결과는 다음과 같다.

| 구분 | 결과 | 근거 |
|---|---|---|
| 항상 포함 | A | 현재 제안 배치 |
| FP8 후보 | B0 (TP16) | 조건을 충족한 배치 중 c32 8K 출력 처리량 최고(219.8 tok/s, A의 1.03배). c1 TPOT은 A의 1.24배 |
| NVFP4 후보 | D42 (TP4×PP2) | 조건을 충족한 1노드 배치 중 c32 8K 출력 처리량 최고(194.6 tok/s, D의 1.00배). KV 용량은 D의 2.2배 |
| D×2 | 실행 | W1 λ*가 D의 2.04배(기준 1.9배 이상) |
| PD | 선정 대상 아님 | 실험 배치다(사전 등록). 2노드에서 λ*가 D×2보다 낮다(3절) |

- B0와 D42가 기준보다 나은 폭(2.6%, 0.5%)은 같은 A를 두 작업에서 실행한 차이(0.5%)와 비슷하다. 1회 측정으로는 기준과 구별하기 어렵다(측정값에 대한 해석).
- 처리량이 높은 DP×EP 배치는 규칙의 지연 상한(c1 TPOT이 FP8은 A의 1.5배, NVFP4는 D의 1.2배 이하)에 걸려 빠졌다.

| 제외된 배치 | c32 8K 처리량(기준 대비) | c1 TPOT 8K(기준 대비) | 131,072 유지 |
|---|---|---|---|
| C8 (mp) | 379.9 tok/s (×1.76) | 44.2 ms (×2.06) | 예 |
| C4 (mp) | 334.4 tok/s (×1.55) | 40.9 ms (×1.90) | 예 |
| C2 | 275.5 tok/s (×1.29) | 41.7 ms (×1.95) | 예 |
| D24 | 246.2 tok/s (×1.27) | 32.3 ms (×1.54) | 예 |
| C16 (mp) | 385.0 tok/s (×1.79) | 48.4 ms (×2.25) | 아니요(61,376) |
| D8 | 268.2 tok/s (×1.38) | 37.6 ms (×1.79) | 아니요(31,616) |

**필요한 결정:** 본 라운드에 처리량 우선 후보(예: C8, D24)를 추가할지 정해야 한다. 이 지연 상한은 SLO보다 엄격하다. SLO 기준(λ*)으로 비교하려면 이 배치들도 본 라운드에서 측정해야 한다. 추가하면 사전 등록에서 벗어난 변경이므로 결과에 그 사실을 표시한다.

## 8. 한계

- 배치마다 1번만 실행했다. 신뢰구간이 없다.
- 작업이 다르면 노드와 시간이 다르다. 같은 A를 두 작업에서 실행한 결과, c32 8K 처리량 차이는 0.5%였다.
- λ*는 2노드 NVFP4 작업(Dx1, Dx2, PD)만 계산했다. 나머지 배치는 W1을 1점만 측정했다. λ*는 도착률 4개 사이의 선형 보간값이라 정밀도가 제한된다.
- PD의 비교 대상(Dx1, Dx2)은 다른 작업에서 측정했다. PD만 GPU 메모리 사용률 0.85로 측정했다(다른 배치 0.9).
- 측정 프롬프트는 합성 토큰이다. 실제 한국어·영어 문장 부하(W1real)는 본 라운드에서 측정한다.
- NVFP4와 FP8의 정확도 동등성은 측정하지 않았다(미확인).
- 각 단계는 약 35분이다. vLLM 이슈 #43547(MoE+DP에서 약 1시간 뒤 멈춤)은 이 길이에서 나타나지 않았다. DP 배치의 장시간 안정성은 미확인이며 본 라운드의 장시간 부하(soak)에서 확인한다.
- Azure ML 작업 런타임이 `UCX_TLS=tcp`를 넣는 이유는 확인하지 않았다. PD 서버만 이 값을 덮어쓴다.
